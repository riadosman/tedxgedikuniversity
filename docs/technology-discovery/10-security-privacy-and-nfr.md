# 10 — Security, privacy and non-functional requirements

Status: **proposed acceptance targets**, not measured results or legal approval. Applies to custom baseline; an external provider must demonstrate equivalent critical behavior or document a rehearsed substitute. Workload assumptions below are test envelopes, not event facts.

## Data and trust boundaries

Public Internet → application → private database/storage → approved email/identity/payment providers → organizer-controlled official tools. Staff devices and downloaded rosters are additional data stores. Private source correspondence contains personal contact and meeting-access information; exclude it from public static assets, indexes, previews, analytics, repository publication and test fixtures.

The privacy review must establish controller identity, processing grounds, notice/rights handling and international transfers. Türkiye's [Law 6698](https://www.kvkk.gov.tr/Icerik/6649/Personal-Data-Protection-Law), Articles 4–12, addresses these topics including data minimization, special-category data, erasure, transfers and security. This is issue identification, not a determination that a particular controller, consent text or hosting arrangement complies. Public [Gedik privacy notices](https://www.gedik.edu.tr/ogrenciler/aday-ogrenciler/kvkk-aydinlatma-metinleri) concern other university processes and do not authorize this event's processing. Q08/X07/X08 must be resolved before personal-data collection.

## Measurable requirements

| ID | Area | Proposed requirement and verification |
|---|---|---|
| NFR-01 | Authentication/session security | Invite-only staff; MFA for organizer, Event Admin and infrastructure operators, preferably all staff. Secure/HttpOnly/SameSite cookies, CSRF on cookie-authenticated mutations; no privileged tokens in localStorage. Proposed idle timeout 30 min, absolute session 8 h; warn before expiry. Step-up within 10 min for roles, broad exports, refunds and retention. Test expiry/revocation and actual scanner shift behavior |
| NFR-02 | Authorization/audit | All reads/mutations/files/jobs/exports enforce role+event+department/ownership server-side. Revoked grants stop authorizing within 60 s. Critical mutation and audit commit together. No application endpoint edits/deletes audit or first admission. AT-07 covers direct object access, stale sessions and mixed roles |
| NFR-03 | Privacy/retention | Require approved purpose/fields/recipients/retention before collection. Proposed limits: roster exports expire in 24 h; action tokens 30 min; QR/delivery secrets deleted 30 days after event; operational attendee/applicant data 90 days after event; redacted security/audit metadata 180 days; backup rotation 30 days. These are review defaults, not statutory periods. Speaker rights, finance and justified holds need separate approved periods. Test purge, anonymization, hold expiry, withdrawal and restored-data handling |
| NFR-04 | Input/files | Bound name 150, email 254, operational note 2,000 characters; normalize Unicode safely and preserve original display. Public forms accept no attachments. Private documents: proposed PDF/PPTX/JPEG/PNG allowlist, 25 MB/file, MIME/signature validation, malware quarantine. Raw HTML/SVG/scripts blocked by default; never execute macros or server-fetch untrusted references. Test malicious uploads, path traversal and reflected/stored XSS |
| NFR-05 | Availability | Target 99.9% reachable admission service during 21 Oct 12:00–17:00, measured with 30 s probes, with no planned maintenance. Probes plus request-error metrics determine outages; not a vendor SLA claim. Static event details available during backend incident through last-approved content. Failures invoke manual plan rather than changing security checks |
| NFR-06 | Backup/recovery | Daily encrypted database backup and provider-supported recovery/log retention, verified before selection. Proposed routine RPO <=24 h; critical registration/event-day RPO <=5 min; RTO <=30 min in rehearsal. If host cannot meet it, choose tested alternative or explicitly reject target before release. Restore database/files/keys and reconcile admissions, cancellations, revoked credentials and privacy deletions from later records before writes resume. Unknown admission state means pause/escalate, not assume unused. Off-host recovery copy and named key custodian required |
| NFR-07 | Transaction performance | On approved staging hardware: 10 check-in requests/s for 5 min, 5 concurrent staff clients; p95 server response <=500 ms and p99 <=1.5 s excluding network; zero duplicate admission/over-capacity results. Proposed 500 synthetic registrations with <=100 allocations; concurrency envelope is not actual demand |
| NFR-08 | Entrance usability | On designated iOS Safari and Android Chrome phones: at least 95/100 legible QR presentations decoded within 2 s in room lighting; p95 scan-to-result <=3 s on venue network. Green admission only after committed receipt. Text/icon feedback, optional sound/vibration; suppress repeated camera frames until staff resets. Staff can reach manual search within two actions |
| NFR-09 | Network/camera failures | Detect request timeout within 5 s, preserve request ID and show unknown outcome. Camera-denied/unavailable error immediately offers search. Test Wi-Fi loss, cellular switch, permission denial, expired login and duplicate scan. No scan accepted offline as globally validated. Camera use requires HTTPS and permission under the browser API ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)) |
| NFR-10 | Accessibility | Target WCAG 2.2 AA for public pages and core staff flows; automated scan plus keyboard/screen-reader checks, visible focus, labelled errors, contrast, zoom/reflow and non-color status. QR cannot be the only admission route. Test 320 px layout and 200% text zoom. Standard reference: [WCAG 2.2](https://www.w3.org/TR/WCAG22/) |
| NFR-11 | Localization/time | Website/admin/talk languages require Q05; no inference from source-document languages. Support Unicode, explicit locale and direction, Arabic RTL if approved, Turkish characters, isolated numeric/time strings. Store timezone-aware timestamps; display Europe/Istanbul with labels. Validate full translated release, not mixed draft locale. No unsupported-language claims |
| NFR-12 | Public performance/browser support | Proposed public p75 LCP <=2.5 s, INP <=200 ms and CLS <=0.1 under defined mobile test profile; initial critical page transfer <=1.5 MB excluding user-triggered media. Test current and previous major stable Chrome/Edge/Firefox/Safari at release; scanner on specifically recorded physical device/OS/browser versions, not emulator-only. Core forms work without camera |
| NFR-13 | Observability | Record structured timestamp, request ID, safe route/result, duration and actor reference. Exclude passwords, QR/action tokens, raw forms, full email, cookies and provider secrets. Alert within 2 min for consecutive health failures or error rate >5%/5 min; alert for pending confirmation mail older than 5 min. Dashboard shows data freshness. Named primary/backup receive and acknowledge test alert within 5 min |
| NFR-14 | Reliability/idempotency | Registration, allocation, cancellation, reissue, import, check-in and conditional payments have durable idempotency/uniqueness. Simulate process crash after commit, before email and during callback. Recover original business outcome; never auto-undo admission due to a delivery error. No successful API response before required transaction commit |
| NFR-15 | Export/data portability | UTF-8 CSV preserving Arabic/Turkish names; neutralize cells starting with formula-trigger characters including whitespace/control prefixes. Include generation time, scope, count and revision, not secrets. Test round-trip/import preview and RBAC. No public/export permalink; proposed download authorization expiry <=15 min within job's retention window |
| NFR-16 | Maintainability/deployment | One codebase, versioned schema, pinned maintained dependencies, documented setup/config owners and ownership boundaries. CI gates domain/permission tests; no critical/high exploitable finding unresolved on exposed path at launch. Named maintainer and deputy can deploy/rollback from written runbook. Restore rehearsal and migration rollback/forward-fix rehearsal before freeze |
| NFR-17 | Abuse prevention | Configurable shared-store controls: proposed progressive delay after 5 submissions per address/hour, soft challenge after 20 submissions per IP/hour, and delay after 5 login failures/15 min. Do not impose a blanket university-NAT registration block. Scanner allowance sized for NFR-07 and bounded burst; test 100 legitimate users on a shared network. Verified owners can correct unverified name input through their action link; no unverified submission permanently monopolizes an email or seat |
| NFR-18 | Event-day readiness | By full rehearsal: configured camera phones, charged power banks, adapters, HTTPS trust, logged-in named accounts, backup connection, printed/versioned roster, supervisor and stop/resume instructions. Time a simulated arrival queue. Example staffing proposal: two operators plus one exception supervisor if available; actual headcount remains Q09/Q10. Critical duties cannot depend on one absent person |

RPO is allowable data-loss window, not a guarantee that lost admissions can be ignored. At the entrance, maintain a controlled receipt/door ledger sufficient to reconcile who was physically admitted when restoring a backup. Restoring a database and immediately scanning tickets without reconciliation is explicitly forbidden.

## Threat scenarios and controls

| Threat | Control | Residual risk / test |
|---|---|---|
| Guessing or sharing QR | 256-bit random bearer credential; authenticated lookup; event/status check; desk identity procedure | Shared legitimate QR can be presented first by wrong holder; no biometric claim. AT-04/05/10 |
| Racing admissions or cancellation | Event/ticket row locks, unique first-admission constraint, durable request receipts | All mutation paths must use service; direct generic admin edits disabled. AT-04/06 |
| Credential leakage through logs/email/image hosting | Redaction, private QR delivery, encrypted material, no referrer/third-party analytics on ticket pages | Email/device compromise requires rotation. AT-08/17 |
| Cross-department enumeration/export | Scoped query/service checks plus field and export permissions | Infrastructure privileged access governed separately. AT-07 |
| Account theft or shared scanner account | MFA, individual roles, session revocation, recovery procedure | Physical device loss; rehearse replacement and revoke. AT-09 |
| Malicious file/CSV/content | Quarantine, allowlists, sanitized rendering, formula neutralization, no arbitrary fetch | Human-linked external document still needs caution. AT-11 |
| Payment forgery/replay | Hosted checkout; signature/status verification; amount/currency matching and event dedupe | Provider outage/late success needs reconciliation. AT-18 |
| Stale manual roster or partial restore | One desk, freeze mutations, ledger reconciliation and supervisor sign-off | Unknown state can delay entry; cannot guarantee distributed offline consistency. AT-10/16 |

## Collection decisions

Keep public registration to name and verified email by default. Survey permission is separate, optional and recorded by purpose/version; no preselected marketing permission. Do not infer that checking a generic privacy checkbox creates every necessary processing or transfer basis. Avoid attendee health details; route access requests through a restricted contact process approved by the controller. Define filming information and handling of minors before collecting relevant data. No automatic transfer to TED, university, sponsor or analytics service without the approved purpose/recipient decision.

No secrets were added to this package. It references private correspondence without reproducing contact details or access codes. A future secret scan should report file/location and remediation owner, not print secret values.
